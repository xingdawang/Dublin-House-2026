# 南都柏林住房邮件统一标准

销售和租赁邮件统一以 **2026-07-24 09:13（Europe/Dublin）收到的《南都柏林住房销售｜2026-07-24｜直达链接修正版》** 为唯一视觉与结构基准。

该基准邮件是完整的原始 HTML 邮件，不是 Markdown 邮件，也不是把 HTML 文本放进普通正文后再自动转换的邮件。后续邮件必须复用同一套 HTML 容器、卡片、颜色、间距、地图和详情结构。

配套模板：`templates/housing_email_template.html`。

## 1. 发送方式：最重要的强制规则

使用 Gmail 发送时必须满足以下条件：

1. 完整 HTML 必须放入 Gmail 发送工具的 `html_body` 字段，或明确使用 `content_type="text/html"`。
2. `body` 只允许放纯文本 fallback，不能放 HTML 源码。
3. 禁止使用默认 Markdown 模式发送完整 HTML。
4. 禁止把 `<html>...</html>` 放进普通 `body` 后依赖系统自动转换。
5. 发出后必须读取原始 MIME 验证：
   - 存在独立的 `Content-Type: text/html; charset="utf-8"` 部分；
   - HTML 中仍存在 `style=`、`table`、`article`、`border-radius`、背景色和链接；
   - 纯文本部分不得出现 `<html>`、`<table>`、`<div>` 等源码。

如果无法保证以上发送方式，停止发送，不得降级成纯文本或 Markdown 邮件。

## 2. 标准主题

- 销售：`南都柏林住房销售｜YYYY-MM-DD`
- 租赁：`南都柏林住房租赁｜YYYY-MM-DD`
- 定时发送不得添加“测试”“补正版”“修正版”等临时后缀。
- 每次计划运行最多发送一封正式邮件。

## 3. 整体 HTML 版式

基准邮件的主要样式必须保留：

- 页面背景：`#f3f5f8`。
- 字体：`-apple-system, BlinkMacSystemFont, 'Segoe UI', Arial, sans-serif`。
- 主内容容器：最大宽度约 `780px`，白色背景，居中显示，左右留白。
- 主标题：约 `28px`，下方显示更新日期与信息核验时间。
- `本期重点`：浅蓝背景、蓝灰边框、圆角卡片。
- 三个摘要：使用兼容邮件客户端的 presentation table 横向排列，显示：
  - `本期条目`
  - `独立地图位置`
  - `当前重点`
- 所有主要模块采用内联 CSS，不依赖外部 CSS、JavaScript 或邮件客户端不稳定的高级布局。
- 房源详情必须使用带圆角和分类颜色边框的独立卡片，不得变成连续纯文本段落。

## 4. 固定内容顺序

1. 邮件标题。
2. `更新日期` 与 `信息核验`。
3. 单段 `本期重点`。
4. 三个摘要卡片：`本期条目`、`独立地图位置`、`当前重点`。
5. `所有房源位置总览` 或 `所有出租位置总览`。
6. 一张正文中可见的 Google Static Maps 总览图，外层链接到 Google Maps 总览。
7. 颜色图例。
8. 使用 `1–9、A–Z` 的紧凑编号地点清单。
9. 按类别展示房源详情卡片；详情编号必须与地图清单一致。
10. 每个当前有效项目必须包含具体详情页链接和独立 `Google Maps` 链接。
11. Watchlist。
12. 状态与核验免责声明。

## 5. Google 地图标准

基准邮件包含以下三层地图能力，三者都必须存在：

1. **可见的 Google Static Maps 总览图**：正文中实际显示地图和编号标记；图片外层可点击进入 Google Maps 总览。
2. **编号地点清单**：地图编号与下方卡片编号一致。
3. **逐房源 Google Maps 链接**：每套当前有效房源卡片均有独立地址链接。

Google Maps Search URL 格式：

`https://www.google.com/maps/search/?api=1&query=...`

Static Maps 图片要求：

- 使用安全配置提供的 Google Maps API key；严禁把真实 key 写入仓库文档、模板或日志。
- 模板中只保留 `{{GOOGLE_STATIC_MAP_URL}}` 占位符。
- 图片建议宽度 `640`，`display:block`、`width:100%`、`height:auto`、圆角约 `10px`。
- 所有当前项目和 Watchlist 地点按分类颜色及 `1–9、A–Z` 编号显示。
- 发送前必须确认地图 URL 可生成有效非空图片。
- 如果执行环境没有可用 key，或无法验证地图图片有效，则停止发送，不得删掉地图后继续发送。

禁止：

- 用纯文字地点列表替代可见地图；
- 只提供总览按钮、不显示地图；
- 只有总览地图而没有逐房源 Google Maps 链接；
- 使用 CID 方案替代基准邮件中的远程 Static Maps 图；
- 在仓库、邮件正文可见文本或运行日志中暴露 API key。

## 6. 编号规则

- 编号依次使用 `1–9、A–Z`。
- 同一地址或同一项目的多个户型共用一个编号。
- 地图、编号清单和详情卡片使用同一套编号。
- `独立地图位置` 显示去重后的地点数量，不是房源条目总数。

## 7. 销售分类与颜色

- 蓝色：Affordable Purchase
- 紫色：开发商新房
- 红色：私人二手 House
- 灰色：待核实、已关闭或 Sale Agreed

销售类别标题固定为：

- `Affordable Purchase`
- `开发商新房`
- `二手出售房 · 价格优先`
- `Watchlist`

卡片要求：

- 分类标题使用对应颜色。
- 重点项目可使用 `2px` 强调边框；普通项目使用 `1px` 同色浅边框。
- 卡片内依次显示：编号与状态、项目／地址标题、价格和户型摘要、说明、详情页链接、Google Maps 链接。

## 8. 租赁分类与颜色

- 橙色：私人整租
- 绿色：Cost Rental
- 灰色：待核实、已关闭或申请结束

租赁邮件复用完全相同的顶部、摘要、地图、编号、卡片、Watchlist 和页脚结构，仅替换分类名称、颜色和业务字段。

## 9. 链接要求

主要房源按钮必须直达具体项目或具体房源详情页。

以下链接不合格：

- 网站首页；
- 搜索结果页；
- 地区或城市列表页；
- 分类页；
- 需要用户进入网站后再次搜索项目的中间页。

无法确认稳定详情页的项目不得用搜索页代替，应明确标记为“直达详情页待核实”。

## 10. Watchlist 与免责声明

- Watchlist 使用灰色标题、浅灰背景、灰色边框的圆角容器。
- 已关闭、Sale Agreed、申请结束或详情链接待核实的条目不得混入当前主要推荐。
- 页脚使用顶部细分隔线、较小灰色字体，说明价格、状态、开放日期和资格条件可能变化，并要求在官方页面再次确认。

## 11. 发送前自动校验

正式发送前必须全部通过：

- HTML 使用模板结构并包含内联样式；
- 邮件通过 `html_body` 或明确的 `text/html` 方式发送；
- 纯文本 fallback 中没有 HTML 源码；
- 标题、更新日期、核验时间和本期重点存在；
- 三个摘要卡片存在且横向排列；
- 可见 Google Static Maps 图存在并可加载；
- 地图编号、编号清单和详情卡片完全一致；
- 每套当前房源有独立 Google Maps 链接；
- 主要房源链接为具体详情页；
- 分类标题、卡片边框颜色和 Watchlist 样式存在；
- 免责声明存在；
- 主题没有“测试”“补正版”“修正版”等后缀。

任意一项失败都不得发送。
